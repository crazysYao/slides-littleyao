## 主題與核心
- **核心概念：問題迴圈**(2026-10-28 改版，設計見 [spec](../superpowers/specs/2026-10-28-ntut-topic-f-problem-loop-design.md))
  - 發現問題 → ① 具體描述 → ② 執行 → ③ 驗證 → ↺ 優化(把落差講得更具體，再跑一輪)
  - 學生隔天要記得的是迴圈；網站是練習迴圈的題材，迴圈也能用在寫履歷、準備面試
  - 三節對應：第一節發現問題、具體描述；第二節執行；第三節驗證與優化
  - 例子：《青之蘆葦》葦人選拔面試(講出來才被看見)、升上 A 隊「言語化的次元不一樣」(講得越細進步越快)
- **主角不是工具，是講師挑工具、串工具的判斷**；工具會換，判斷帶得走
- **成品**：個人網站(本機 `site/index.html`，不上線)
- **失敗條件(講師定)**：學員只會照著講師給的 Prompt 做，沒有轉成自己的內容
  - 對策：Prompt 一次比一次給得少，見「Prompt 遞減」

## 工具與講師判斷

| 工具 | 角色 | 選它的理由 | 要不要講給學員 |
|---|---|---|---|
| Obsidian | 知識庫 | 本機 .md，任何 AI 都讀得懂，資料主控權在自己手上 | 講(判斷時刻) |
| Claude Code | 講師示範的 Agent | 講師自己付費的工具，整個流程現場跑一遍 | 講：學員接自己的 Agent 服務也能完成，例如 Codex、Cursor |
| OpenCode Desktop | 學員的免費選項 | 免費、不用終端機 | 只給沒有付費 Agent、又想跟做的人 |

- **不強迫實作**(2026-11-03)：講師用 Claude Code 跑完整個流程；學員只看也行，想跟做就用自己的 Agent
  - 實作頁一律標「可跟做」；投票與「第一直覺」頁，沒跟做的人改評講師的網站

| 時段 | 給多少 | 學員要做的事 |

- **呼應主線**：Prompt 也是自己的資料，存進知識庫，換任何 Agent 都能用

### Prompt 原文
**基本資料(第一節，貼給聊天 AI)**
```
我要建求職用的知識庫。請列出下面 5 題，等我一次回答完：
1. 學校、科系、年級
2. 想做什麼工作
3. 一個專題或作業：做了什麼、我負責哪塊
4. 一段打工、實習或社團經歷
5. 會用的工具，各做過什麼
我答完後，整理成一則 Markdown 筆記，分成關於我、學歷、專題、經歷、技能五段，內容用短條列。只用我說的，沒提到的寫「？」，不要編。
```

**① 完整：Agent 訪問你**
```
請讀這個資料夾裡所有 .md 筆記。你是求職顧問，先從標了「？」的地方問起，一次問我一個問題，
幫我補齊缺的細節：我負責什麼、用了什麼工具、有沒有數字成果。
我回答後，把答案寫進對應資料夾的筆記。問完 5 題就停。
```

**② 填空：產出網站 v1**
```
讀這個資料夾的所有筆記，做一個給＿＿(誰會看：面試官、客戶、社團學弟妹)看的個人網站，
風格是＿＿，最想讓對方記住的一件事是＿＿。
只能用筆記裡的內容，不要編造經歷。存成 site/index.html，CSS 寫在同一個檔案，手機看也要好看。
```

**③ 骨架：讀者審稿**(投影片一張卡，學員自己補完)
```
你是＿＿(Prompt ② 填的讀者)，打開這個網站看 30 秒。
告訴我：你記住了什麼？想跳過哪裡？還想知道什麼？
我挑一點請你改：＿＿。
```

## 第一節 09:00–09:50｜發現問題，具體描述

- **09:04 安裝，選配(3)**：想跟做的人才裝，安裝的同時聽下一段
  - Obsidian：`https://obsidian.md/download`
  - OpenCode Desktop：`https://opencode.ai/download`(沒有付費 Agent 的人才裝)
  - 🍎 Mac：蘋果選單 →「關於這台 Mac」，Apple M 系列選 Apple Silicon，Intel 選 Intel；.dmg 拖進「應用程式」

- **09:07 發現問題(3)**：三頁，指令 → 投票 → 揭曉
  - 講師切到 AI 畫面，只打「幫我寫自我介紹」，不給任何資料

  - 口頭問「問題出在誰？AI 不夠強嗎？」，再揭開：AI 的空泛，是我造成的(它不認識你，因為你什麼都沒說)
  - 備案：現場 AI 或網路出狀況，放事先產生的結果截圖
- **09:10 問題迴圈(7)**：兩頁，先只放迴圈圖(0:00–3:00)，再加青之蘆葦與網站對照(3:00–7:00)
  - 0:00–1:00 回到自我介紹：問題不是 AI 爛，是講得不夠具體 → 發現問題
  - 1:00–3:00 沿圖走一圈，說今天三節各在哪一步
  - 3:00–5:30 青之蘆葦兩個場面：選拔面試(具體描述)、升上 A 隊(優化)
  - 5:30–7:00 網站對照：「不好看」改不動；「標題太小、第一眼看不出我會什麼」AI 改得動；寫履歷、準備面試也一樣
- **09:17 判斷時刻：為什麼是 Obsidian(3)**
  - 可用素材：講師網站 Talks 區的 3 小時實作課經驗(例如開南大學 30 人電腦教室)
- **09:20 講師示範＋可跟做：建知識庫(25)**：原本的環境檢查(10)拿掉，時間併進這段
  - 下載範本 vault：`關於我／學歷／專題／經歷／技能`，每個資料夾一則範例
  - 投影片放一則好筆記，標出三個要素：做了什麼、我負責哪塊、有什麼數字
  - 0–5 講師示範：用 Obsidian 開啟範本，把「基本資料 Prompt」貼給聊天 AI 跑一輪
  - 5–20 學員：貼 Prompt、一次回答 5 題，把 AI 回的整段貼進一則「我的基本資料」筆記，不用自己開資料夾分類；想不起來的留「？」，有舊履歷可一起貼

## 第二節 10:00–10:55｜執行
- **10:00 暖身搶答(5)**：考迴圈的步驟(空泛時下一步是什麼、驗證要做什麼)
- **10:05 聊天 AI vs Agent(8)**：前段用「Agent 是什麼」頁，後段並排比較

  - 講師示範用 Claude Code，換成任何 Agent 流程都一樣(「Agent 是什麼」頁列出 Claude Code、Codex、Cursor、OpenCode)

- **10:35 講師 Demo：產出網站(3)**：示範填 Prompt ② 的空格，說明空格怎麼想
- **10:38 找風格(3)**：Synora 連結開 Pinterest 搜「personal website design」，挑 1–2 個喜歡的，用三個詞描述，當作 Prompt ② 的風格空格

- **10:42 實作：網站 v1(10)**
