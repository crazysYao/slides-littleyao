# 功課：人類專注心理 × 簡報設計

> 狀態：初稿(2026-10-20)，待討論。
> 目的：整理「人能專注多久、怎麼讓人保持專注」的研究，轉成不同時長簡報的設計準則。
> 北科大課程只當參考範例，不是本文主體。

---

## 一、研究重點(附可信度)

可信度標記：
- ✅ 證據穩固，可以放心當設計依據
- ⚠️ 有研究但有爭議，或只在特定條件成立
- ❌ 常見迷思，不要引用

### 1. 「人只能專注 10 分鐘」證據不足 ⚠️
- Bradbury(2016)回頭檢查 10–15 分鐘的說法
  - 最常被引用的出處，其實幾乎沒在討論注意力
  - 其他測量研究方法有問題，多半是主觀紀錄
- **最一致的發現：專注度差異最大的來源是講者，不是形式**
- 設計意涵：不要把「10 分鐘」當硬規則，但「固定節奏換狀態」仍然有用(見下一點)

### 2. 注意力是斷斷續續的，而且越後面越碎 ✅
- Bunce 等(2010)讓學生上課時按按鈕回報分心
  - 多數分心不到 1 分鐘
  - 專注／分心的循環隨課程進行越來越短
  - 投票題與現場示範後，分心明顯減少，**效果會延續到下一段講授**
- Risko 等(2012)、Farley 等(2013)：講越久，分心越多、記住越少
- 設計意涵：問題不是「何時失焦」，而是「多久重新拉回一次」

### 3. 中途插入小測驗，分心減半 ✅
- Szpunar、Khan、Schacter(2013, PNAS)，線上講課影片
  - 沒有測驗組：約 40% 時間在分心
  - 中途插入小測驗組：降到約 20%
  - 學得更好、最後考試焦慮更低
- 限制：單一講次、單一主題、線上影片情境
- 設計意涵：投票／搶答不只是炒氣氛，是「強迫提取」，同時拉回專注

### 4. 主動學習勝過純講授 ✅
- Freeman 等(2014, PNAS)，225 篇 STEM 研究的統合分析
  - 主動學習：考試成績提升 0.47 個標準差
  - 純講授：不及格的勝算是 1.95 倍
  - 小班效果最大，但跨班級規模都成立
- 設計意涵：時長越長，「學員自己動手」的比例要越高

### 5. 工作記憶一次大約裝 4 個單位 ✅
- Cowan(2001)：專注焦點容量平均約 4 個 chunk
  - Miller 的「7±2」是較早、較粗略的說法
  - 確切數字仍有爭論(4–5)
- 設計意涵：一頁、一段、一節的重點都控制在 3 個以內

### 6. 多媒體學習原則 ✅
Mayer 的原則中，跟簡報最相關的四條：
- **一致性 Coherence**：刪掉無關的裝飾、段子、背景圖
- **提示 Signaling**：用箭頭、標色、標題標出重點
- **重複 Redundancy**：口說＋圖，勝過口說＋圖＋整段字
  - 投影片放講稿全文會傷害學習
- **分段 Segmenting**：把內容切成小段，讓人有喘息點

### 7. 午後低谷 ✅
- 下午約 14:00–16:00 警覺度下降，是生理時鐘現象
- 設計意涵：午餐後不要排純理論，排實作、討論、走動

### 8. 「短暫休息能重置專注」⚠️
- Ariga & Lleras(2011)：任務中短暫切換，可避免專注衰退
- Helton & Russell(2012)498 人重做，**沒有重現**
- 設計意涵：中場休息仍然合理，但不要宣稱「科學證實每 X 分鐘休息一次」

### 9. 「手機放桌上就會變笨」❌(證據偏弱)
- Ward 等(2017)「Brain drain」
- 多個預先註冊的直接重製實驗都沒有重現
- 設計意涵：可以請學員收手機，但不要拿這篇當理由

### 10. 「人類專注力只有 8 秒，比金魚短」❌
- 源自行銷報告，不是學術研究
- 不要放進簡報

### 11. 提取練習勝過重讀 ✅
- Roediger & Karpicke(2006)
  - 5 分鐘後考：重讀組較好
  - 2 天、1 週後考：測驗組明顯較好
  - 重讀組反而對自己的記憶比較有信心
- 設計意涵：每節開頭的回顧搶答，是長時長課程最值得投資的互動

### 12. 間隔練習 ✅
- Cepeda 等(2006)統合 317 個實驗
  - 分散學習勝過集中學習
  - 想記越久，間隔要拉越長
- 設計意涵：多天課程要讓同一概念隔天再出現

### 13. 筆電多工連累旁人 ✅
- Sana、Weston、Cepeda(2013)
  - 上課多工的人：測驗分數較低
  - 看得到別人螢幕的人：分數也較低，而且自己沒察覺
- 作者不主張禁用筆電，建議跟學生說明研究
- 設計意涵：想請學員收手機或關分頁，引用這篇，不要引用 brain drain

### 14. 好奇心強化記憶 ✅
- Kang 等(2009)
  - 越好奇的題目，越願意花代價知道答案
  - 好奇時看到的意外答案，1–2 週後記得更好
- 設計意涵：先拋問題、晚一點揭曉，比直接講答案好記

### 未在本次查證、但屬常見共識
- 序列位置效應：開頭和結尾最容易被記住
- 峰終定律：體驗評價取決於高峰和結尾
- 情緒與驚奇會強化記憶
- 引用前建議再查原文

## 二、通用設計單位：「一段」

所有時長都可以用同一個積木組起來：

```
一段 ≈ 10–20 分鐘
  ├─ 進場：一個問題或反差(拉注意力)
  ├─ 主體：最多 3 個重點
  └─ 出場：狀態切換(投票／搶答／實作／討論／示範)
```

- 依據：注意力會碎、切換後能延續(研究 2、3)
- 講者越有吸引力，一段可以越長(研究 1)
- 時長越長，「出場」越該是學員動手，而不是講者換個話題

## 三、各時長對照

### 1 小時(單場演講／分享)

**推薦架構**
| 時間 | 內容 |
|---|---|
| 0–5 | 開場鉤子：一個問題、反差或故事 |
| 5–50 | 3 段 × 約 15 分，每段一個重點，段尾一次互動 |
| 50–55 | 收尾：回扣開場，給一句可帶走的話 |
| 55–60 | QA |

**說明方式**
- 全場只有一個核心句，三個重點都在撐它
- 不需要中場休息，靠 3–4 次狀態切換維持
- 開頭和結尾最被記住，把最重要的話放這兩處(序列位置效應，未查證)

**Know-how**
- 互動用低成本的：舉手、投票、一題搶答
- 不安排長實作，10 分鐘以上的實作會吃掉講授時間
- 投影片字少，講稿放備註

### 3 小時(半天課程／工作坊)

**推薦架構**
| 時間 | 內容 |
|---|---|
| 第一節 50 分 | 觀念：建立共同語言，3 段 |
| 休息 10 | |
| 第二節 50–55 分 | 方法／工具：開頭回顧搶答，3–4 段 |
| 休息 10 | |
| 第三節 50–55 分 | 應用：以實作和討論為主，講者少講 |

**說明方式**
- 每節一個子主題，節與節之間有明確的「我們現在在哪」
- 每節開頭用 2–3 題回顧，強迫提取上一節內容
- 第三節疲勞最高，主角換成學員
- 一個貫穿全場的作品(例如 v1 → v3 → 定稿)，讓學員有進度感

**Know-how**
- 講授比例由前往後遞減：約 60% → 50% → 30%
- 休息前留一個懸念，休息後先解答
- 上午場和下午場要不同：下午場把實作往前挪

**參考範例**：北科大課程 [lesson-plan.md](../ntut-ai-course/lesson-plan.md) 就是這個骨架

### 全天(6 小時左右)

**推薦架構**
| 時段 | 內容 |
|---|---|
| 上午 2 個模組，各 75–90 分 | 觀念與方法，模組中間休 10–15 |
| 午餐 60 | |
| 午後第一個模組 | **實作或分組**，不排理論(午後低谷) |
| 最後一個模組 | 成果發表＋整合回顧 |

**說明方式**
- 每個模組本身就是一場「1 小時架構」
- 一個貫穿全天的情境或專題，每個模組推進一步
- 每個模組開頭：回顧＋今天地圖上的位置
- 結尾讓學員產出一份可帶走的成品

**Know-how**
- 講者體力也是資源，要排自己能喘息的時段(學員實作時)
- 分組讓學員互相教，講者不必撐全場
- 結尾比開頭重要(峰終定律，未查證)：最後一小時要有高峰

### 多天／系列課

**推薦架構**
- 第一天：建立共同語言與目標
- 每天：開頭回顧前一天 → 新內容 → 實作 → 當天收束
- 天與天之間：小作業或練習
- 最後一天：成果發表

**說明方式**
- 刻意把同一概念隔天再出現一次(間隔效應)
- 每天開頭的回顧搶答，用前幾天的題目混著出

**Know-how**
- 累積型專題，比每天獨立的主題更能維持動機
- 每天結束時預告明天，製造期待

## 四、對應適合的 skill

> 這裡的 skill 指本機 Claude Code 可用的 skill。

### 所有時長都會用到
| 階段 | skill | 用途 |
|---|---|---|
| 定題 | `superpowers:brainstorming` | 釐清對象、目標、時長 |
| 挖觀點 | `hcs-thinking` | 找出講者獨有的論點 |
| 查證 | `anthropic-skills:deep-research` | 引用研究前確認出處 |
| 簡報策略 | `anthropic-skills:presentation-strategist` | 需求訪談＋敘事框架，產出 Canva／Google Slides／PPTX 用的內容 |
| 製作 | `create-slide`、`slide-authoring` | open-slide 簡報 |
| 修改 | `apply-comments` | 套用檢視器留言 |
| 圖解 | `artifact-diagramming`、`dataviz` | 流程圖、數據圖 |

### 依時長加上
| 時長 | 加上的 skill | 原因 |
|---|---|---|
| 1 小時 | 上表即可 | 互動簡單，舉手或單題投票就夠 |
| 3 小時 | `synora:author-deck`、`synora:verify-deck`、`synora:operate-classroom` | 需要投票、搶答、排行榜做回顧 |
| 全天 | 同上，加寫教案文件 | 模組多，需要教案控時間 |
| 多天 | 同上 | 跨天回顧題庫要累積 |

## 五、自我檢查清單

- [ ] 全場核心句只有一句
- [ ] 每段重點 ≤ 3 個
- [ ] 每 10–20 分鐘有一次狀態切換
- [ ] 互動中有「提取」型(搶答、回想)，不只「意見」型(投票)
- [ ] 每節開頭有回顧
- [ ] 午餐後排實作
- [ ] 投影片沒有整段講稿
- [ ] 結尾回扣開場
- [ ] 引用的研究都查過出處，沒有用到 ❌ 項目
