# 簡報內建課堂互動系統(取代 Slido)設計

> 狀態：設計待確認(2026-10-19)。第一個使用場景：北科大 AI 新秀課 11/26 09:00–12:00。

## 為什麼要做
- Slido 嵌入簡報後，投影畫面只顯示後台「目前啟動」的那一題，不會跟著簡報換頁；講者得用手機另外切題，切走的題目票數還會歸零。講者覺得「Slido 不符合我的要求」。
- Wayground 帳號是商業版 14 天試用，上課前會到期。
- 講者要的是：**題目就在簡報裡**，翻到哪頁就作答哪題；學生直接在畫面上作答，老師即時看到結果。
- 之後每份簡報都要能用，不是一次性的。

## 使用者與情境
- **老師(講者本人，目前只有一位)**：筆電接投影機播放老師版；手機也登入老師版當遙控器(翻頁、開題、公布)。
- **學生(50 人以內，教室網路正常)**：用教室電腦或自己的手機開學生連結作答，兩種裝置都要支援。

## 目標
1. 學生版與老師版是**不同連結**。
2. **學生版**
   - 第一次進入輸入暱稱即可，不用註冊、不用裝 App；投影上提供 QR code 與短網址。
   - 預設**跟著老師翻頁**；可以隨時切換成「自己翻」，再切回「跟隨老師」。
   - 看得到一般簡報頁，**看不到 Demo 頁與講稿**。
   - 投票頁、搶答頁可以直接在畫面上作答。
   - 老師按「公布」之前看不到全班結果與正解；公布後學生畫面也顯示結果與正解。
3. **老師版**
   - 整個老師版連結都要 **Google 登入**才打得開(只允許講者的 Google 帳號)。
   - 完整簡報，含 Demo 頁與講稿。
   - 投影畫面即時顯示作答統計(人數、各選項比例)。
   - 控制：翻頁(同步給學生)、開放作答、公布結果與正解、顯示排行榜。
   - 筆電與手機可同時登入老師版，任一端操作，兩端與學生端同步。
   - **場次**：老師按「開新場次」產生新的場次與學生連結(含 QR code)；舊場次結果保留、可回看。
4. **搶答**：依「答對＋速度」計分，有排行榜(顯示暱稱)。投票結果匿名顯示。
5. **可重用**：互動元件做成共用元件，之後任何一份簡報都能放投票頁、搶答頁。

## 非目標
- 不做多位老師帳號管理(之後要再說)。
- 不做課後匯出(講者沒有選)。
- 不做離線模式。
- 不追求「技術上絕對拿不到」Demo 與講稿：只要學生連結裡沒有這些內容，且老師連結有登入保護即可(見「隱藏內容」)。

## 失敗條件(就算功能都有也算失敗)
- **學生加入太麻煩**：要註冊、要裝 App、步驟多。目標是「掃碼 → 輸入暱稱 → 開始」。
- **翻頁或結果有延遲**：老師翻頁後學生畫面要在約 1 秒內跟上；投票數字要即時跳動。
- **投影畫面不好看**：統計圖、排行榜要符合簡報既有的對話框聊天風格(design token、圓角、三問代表色)，不能像外掛的工具畫面。

## 講者已決定的做法
| 項目 | 決定 |
|---|---|
| 後端 | **Cloudflare**：Workers＋Durable Objects(即時房間、WebSocket)＋Cloudflare Access(老師 Google 登入)。網域 `littleyao.me` 已在 Cloudflare。 |
| 程式位置 | **同一個 repo**，放寬「只能改 `slides/<id>/`」規則：新增共用互動元件資料夾與 Cloudflare 程式資料夾，並更新 `CLAUDE.md`、`AGENTS.md` 的規則說明。 |
| 老師登入 | Google 登入；整個老師版都在登入之後。 |
| 場次 | 老師按「開新場次」。 |
| Slido | 簡報拿掉 Slido 嵌入；Slido 活動保留當備援(不刪)。 |
| 時程 | 越快越好，先做出可彩排的版本再補完。 |

## 審查後補充的決定
### 講者決定
- **分步內容跟老師同步到每一步**：學生畫面上 `<Steps>` 的揭示進度跟老師一致，不可提前看到。open-slide 沒有公開的程式控制 step API，建置者需自行解決(例如學生版自行渲染頁面與 step)。
- **手機遙控器＝控制面板＋講稿**：大按鈕(上一步／下一步、開始作答、結束、公布、排行榜、開新場次)，顯示目前頁標題、頁碼與講稿；不渲染簡報畫面。
- **老師帳號**：只有 `a39795979@gmail.com`，筆電與手機都用它登入。
- **Cloudflare 權限**：講者建立 API token(Workers、Durable Objects、Access、DNS 編輯)存於 `~/.secrets/`，建置者用它部署與設定；講者只需手動完成 Google OAuth 用戶端。Durable Objects 使用免費方案(SQLite 版)，不花錢。

### 建置者的判斷(Claude 代決，講者可推翻)
- **Demo 頁的範圍**：北科大簡報目前只有第 26 頁「Demo：這堂課是怎麼備出來的」屬於老師專屬。標記方式由共用元件提供(例如頁面上的 teacherOnly 標記)，以「頁面 ID」而非頁碼同步，避免學生版少頁後頁碼對不上。
- **老師停在老師專屬頁時**：學生畫面顯示「老師正在示範」佔位畫面，不顯示內容。
- **題目與正解**：題目寫在簡報頁的共用元件 props 中；**正解只存在老師版**，老師開題時送到 Durable Object，公布時才廣播給學生。學生版的建置產物不得含正解。
- **網址與部署**：學生版留在公開站 `slides.littleyao.me`(Vercel)，公開建置不得含老師專屬頁、講稿與正解；老師版放在 Cloudflare、Access 保護的網域(例如 `live.littleyao.me`)。Vercel 自動部署維持。短網址先用學生版網址＋QR code，不另外買短網址。
- **手機與筆電同時操作**：以伺服器收到的順序為準，後到者覆蓋。
- **重用範圍**：這一輪只遷移北科大簡報，但元件與建置方式做成通用，其他簡報之後要用時不需改系統。

## 現況(建置者需要知道)
- 簡報框架是 `@open-slide/core`(1.19.x)：每份簡報是 `slides/<id>/index.tsx`，export `default: Page[]`，可另 export `notes`(講稿陣列)、`meta`、`design`。提供 `useSlidePageNumber()`、`useIsActivePage()`、`<Steps>`；設定檔 `open-slide.config.ts` 有 `slidesDir`。
- 公開站 `https://slides.littleyao.me` 在 **Vercel**(main 自動部署，SPA)。DNS 在 Cloudflare，`slides` 記錄是 DNS only。
- 北科大簡報：`slides/ntut-three-questions/index.tsx`(36 頁)，目前第 4、17、21、27、30、34 頁是 Slido 嵌入(`SlidoWall`)。題目與正解見 `docs/ntut-ai-course/lesson-plan.md`：投票 7 題、搶答 9 題(暖身 4、複習 5)。
- 目前 repo 規則：不可加 npm 套件、不可改 `package.json`、`open-slide.config.ts`。放寬範圍見下方「留給建置者」。

## 隱藏內容(學生看不到 Demo 與講稿)
- 學生連結不應包含 Demo 頁與講稿；老師連結整個在 Cloudflare Access 後面。
- 因此**老師版不能只是公開站上的一個不公開網址**：公開站是 SPA，所有簡報都在同一份建置裡，任何人知道網址都打得開。老師版要放在 Access 保護的網域下(例如 Cloudflare 上的 `live.littleyao.me/teach/...`)，或用其他方式確保公開建置裡沒有老師專屬內容。具體做法留給建置者，但要符合上面兩點。

## 互動的行為細節
- **投票頁**：顯示題目與選項；學生點選後送出，可在公布前改選(建置者決定是否允許改選，預設允許)。老師端長條圖即時更新，顯示作答人數 / 已加入人數。
- **搶答頁**：老師按「開始」→ 學生畫面出現題目與倒數(預設 20 秒，可每題設定)→ 時間到或老師按「結束」停止作答 → 老師按「公布」顯示正解與比例 → 老師可切到排行榜。計分公式留給建置者(類似 Kahoot：答對才得分，越快越高)。
- **跟隨模式**：學生預設跟隨；切成自己翻時，畫面上要有明顯的「回到老師目前頁」按鈕。自己翻也只能翻到學生版有的頁面。
- **斷線**：學生或老師斷線後自動重連，回到目前頁與已作答狀態，不需重新輸入暱稱(同一裝置)。

## 留給建置者
- Worker、Durable Object 的資料結構與 API 設計、WebSocket 訊息格式。
- 學生版的實作方式：例如另一份 open-slide 簡報、或一份只有一頁、自己根據老師狀態切換內容的簡報、或獨立頁面。要考量 open-slide 沒有公開的「程式控制翻頁」API。
- 老師版放在哪個網址、如何在 Cloudflare 上提供(例如 Workers 靜態資源)與如何建置出不含/含老師內容的兩份輸出。
- 共用元件資料夾的名稱與位置；是否需要放寬「不可加套件」(優先不加，只用 React 與 Web API；Worker 端的開發工具如 wrangler 是否要進 `package.json` 由建置者判斷並說明)。
- 計分公式、改選規則、QR code 產生方式(不加套件的話需自行實作或用現成服務)。
- 視覺：沿用北科大簡報的 design token 與元件風格。

## 講者需要動手的事(建置者要寫成步驟)
- 在 Google Cloud 建立 OAuth 用戶端，供 Cloudflare Access 的 Google 登入使用。
- 在 Cloudflare 後台(或提供 token 讓建置者用 API)設定 Access 應用程式、Workers 部署所需權限。
