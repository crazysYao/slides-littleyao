### A1 複選投票：開場「你用 AI 做過哪些事？」
- 效果：一排選項卡片，學員可複選後送出，Presenter 看全班分布(無正確答案)
- 為什麼採用：現在第 2 頁只有「有／沒有」兩個選項，看不出全班起點；複選一次就知道誰只會聊天、誰寫過履歷、誰用過 Agent
- 內容(選項待講師改)：還沒用過／問問題／寫報告作業／寫履歷或自我介紹／準備面試／寫程式／用過會自己動手的 Agent(Claude Code、Codex)
  - 保留「用過 Agent」這項，原本講稿「有不少人選有就請他們舉手」照用
- 實作：build-deck 新增 `multiChoice` 版型(schema 只有 `question`、`choices`)

### A2 完成確認鈕：可跟做頁加「我做好了」
- 效果：複製卡下方一顆按鈕，學員做完按一下，Presenter 即時看到幾個人完成
- 為什麼採用：**助教 0 位**，講師一個人看不到台下進度；有人數就知道該等還是往下講
- 位置與文字(待講師改)

  - 卡片標題補一句「只看的人不用按」，避免沒跟做的人以為自己落後
- 實作：build-deck 已有 `checkpoint` helper，新做「複製卡＋確認鈕」版型；複製卡縮短高度讓按鈕放得下(Eric 第 68 頁同樣做法)

### A3 Q&A 打字提問
- 效果：Q&A 頁放打字框，學員匿名送出問題，講師挑著回答、可公布
- 為什麼採用：害羞、不敢舉手的人也能問；第 18 頁已經用過同一元件，學員會操作
- 實作：`qa` 版型加 opentext 元件；qa 是深色底，要 render 確認元件在深底上看得清楚，不清楚就改成淺底

### A4 作品網址繳交：不採用
- 我們的網站存在學員自己電腦(`site/index.html`)，**不上線**，沒有網址可交；截圖作業(第 53 頁)已涵蓋

### A5 RWD 互動頁：這次不採用，下一版再考慮
- 效果：示意框自動在手機、平板、筆電、桌機間切換，右邊列出「手機一欄、平板兩欄…」的具體規則
- 很適合主題：「手機看也要好看」講不清楚 → 改講尺寸和規則，正是**具體描述**
- 不採用的原因
  - 要重寫成黃黑版 html＋script，是整份唯一的自寫 script 頁，推送後還要另外實測
  - 至少要 2 分鐘，但時間軸的緩衝上一輪已給作品牆(引玉只剩 2 分)
- 若講師想要：可放第三節第一直覺(第 52 頁)之前，時間要從讀者審稿 14 分扣

### A6 人工 vs AI 時間長條：不採用
- 訊息不合：那頁講「AI 幫你省多少時間」，主題 F 的核心是「講清楚、一輪一輪改」

### A7 進場動畫：不採用
- Synora 原生元件沒有任何動畫欄位(已查 schema)；Eric 的動畫來自整份 80 頁都用 html 元件自寫 CSS

## B. icon 去 AI 味

### 作法
- 新增 `synora/icons.mjs`：約 20 個線條 icon 的 path(24×24、線寬 2、圓角線帽)
  - 取自 Lucide(ISC 授權)，檔頭註明出處；不加任何套件依賴
- build-deck 新增 `icon(name, x, y, size, color)`，輸出 Synora 原生 `svg` 元件(第 14、35 頁的 svg 已證明兩個畫面都正常)
- 配色照現有視覺規則：白卡上黑線、黃底上黑線、深色底上白線；黃色只當填色
- `topic-f-content.mjs` 只把 emoji 換成 icon 名稱(例 `'💻'` → `'laptop'`)，內容核心仍不含版面
- icon 尺寸：卡片內 28px；左側黃色大區塊 64px
