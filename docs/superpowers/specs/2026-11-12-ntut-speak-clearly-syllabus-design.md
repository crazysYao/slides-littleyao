## 為什麼改
- 已合併的 OpenCode＋Vercel 版，第一節有 22 分鐘連續在裝軟體和註冊，學員看不出跟網站的關係；Node 或 Vercel 登入失敗就沒有成品，而且沒有停損
- Gemini Canvas 版把工具鏈拿掉，但空出的時間拿去講 Prompt、Skill、MCP 三個名詞，名詞跟學員手上的作品接不起來
- 講師 2026-11-12 決定全部段落重新討論：先定核心，再逐段決定留或不留
- 佈局定稿前用三個獨立審查角度檢查過（學員走查、時間與專注節奏、脈絡與事實），本文件已套用審查結果，見〈審查紀錄〉

## 講師決定的事
- **核心**：教會學員「把自己講清楚」。AI 回得空泛，是因為它不認識你
  - 網站是用來證明的載體
  - 問題迴圈（發現問題 → ① 具體描述 → ② 執行 → ③ 驗證 → ↺ 優化）是方法，不是主角
- **三節主題**：講清楚 → 做出來 → 改更好＋應用
- **時間**：50 分上課＋10 分休息，共三段；第三段後面的 10 分鐘全部給 QA
- **開場**：先做課綱簡介（含秀終點），再問大家用 AI 的經驗（兩題多選：用 AI 做過哪些事、現在有沒有付費的 AI 服務）
- **開場三個例子的順序與分工**
  1. 「幫我寫自我介紹」→ 揭曉：AI 的空泛，是我造成的
  2. 手搖飲 → Prompt＝點餐單；一次次調得更好＝提示詞工程
  3. 女朋友「好煩喔」→ AI 不會主動追問，所以讓 AI 來訪問你
- **學員工具**：全程只用聊天 AI 的網頁預覽
  - Gemini Canvas、ChatGPT Canvas、Claude Artifact 三選一
  - 投影片與講稿以 Gemini 為主線；ChatGPT、Claude 只在「卡住時換一個」出現
  - 學員不裝任何軟體、不操作 Agent
- **講師**用付費 Claude 示範
- **名詞只講三個**：Prompt（手搖飲）、Skill（咖啡店章節）、Context（一天上八堂課、A／B 老師、互動示意圖）。不講 MCP、Agent
- **學以致用**
  - Skill 講完，學員自己做一個 Skill 並上傳；講師一步步引導並提供 Prompt
  - Context 揭曉完，馬上開新對話用一次
- **作品上傳**
  - v1 不上傳，只用投票確認進度
  - Skill 上傳一次
  - v2 上傳一次，截圖或 HTML 檔都收，上傳後網站牆互投
  - Canvas 分享連結改成選做
- **省額度**不另開一段，綁在登入、Skill、fix、Context 四個地方講
- **第三節後半是應用**（學員只看）：講師用自己的網站上架 Vercel；Obsidian 把同一份資料變成履歷、面試稿
- **收尾**：QA 10 分鐘，不放收尾金句
- **採用的新素材**
  - 手搖飲情境
  - 咖啡店 Skill 章節 7 頁，第 2、3 頁用講師提供的兩張拿鐵照片，做成「有 Skill／沒有 Skill」分頁切換
  - Context 互動示意圖，仿照講師提供的互動頁做法
- **審查後講師同意的五項調整**
  1. v2 留在原對話改；Context 的學以致用改成開新對話、只貼基本資料副本、產出一段面試自介
  2. Gemini 學員建真的 Skill，其他工具的人存成文字；咖啡店章節補一句銜接
  3. 登入提前到 09:04 跟加入 Synora 一起做；Vercel 示範縮短並改用 Vercel Drop
  4. Context 段維持 7 分鐘、三樣放一起；八堂課的說法改成跟示意圖一致
  5. 緩衝裡拿 1 分鐘回顧帶走的三樣東西和迴圈四步（是回顧，不算金句）

## 目標／非目標／反目標
- **目標**
  - 每位學員下課帶走三樣：一份「我的基本資料」、網站 v2（已上傳 Synora）、一個自己做的 Skill
  - 學員能說出：AI 空泛是因為我沒講清楚；Prompt、Skill、Context 各是什麼
  - 學員至少親手做過一次「開新對話只貼需要的東西」
- **非目標**
  - 學員自己上線 Vercel、自訂網域、GitHub
  - 學員安裝任何軟體、操作 Agent
  - 講 MCP、Agent 這兩個名詞
- **反目標**
  - 學員一直在設定環境、不知道在幹嘛
  - 學員只會照貼講師的 Prompt，網站內容不是自己的
  - 上傳的作品或分享連結出現私人手機、身分證、住址
  - 有人下課時沒有可交的作品（截圖也沒有）
  - 名詞講完沒有立刻用到

## 條件
- 學員約 20 人，剛畢業求職中，沒有程式背景，多數沒有付費 AI
- 自帶筆電，也可能有人只帶手機；助教 1 位；課前聯絡不到學員
- 簡報與互動跑在 Synora 專案「讓 AI 一開口就懂你（求職網站上線版）」（id `aef695ce-dd63-4375-a02a-d134f3100159`，2026-11-12 查到 50 頁、saveSeq 6、學員入口為草稿）
- 已查證的事實（2026-11-12）
  - **Synora 元件**（讀 plugin 0.9.3 的本機檢視器）
    - 「網頁作品上傳」`webProject`：收 `.html`／`.htm` 檔或作品網址，可開互投
    - 「作業提交」`homework`：收圖片／影片與文字（模式有「圖片／影片上傳」「圖片／影片＋提示詞」與全功能）
    - 「作品展示牆」`showcase`：連到某個作業提交，現版 `s2-v1-wall` 就是這樣用
  - **Gemini Skills**（[Google 說明頁](https://support.google.com/gemini/answer/18560919)）
    - 個人 Google 帳號、18 歲以上可用；工作與學校帳號尚未開放
    - 建立：側邊欄「自訂 → Skills → 建立 → 手動建立」，填名稱、說明、指示；名稱要小寫、用連字號
    - 使用：對話裡打 `/` 加 Skill 名稱；Gemini 也可能自動套用
    - 頁面沒寫免費帳號與手機 App 能不能用
  - **Vercel Drop**（[Vercel 文件](https://vercel.com/docs/drop)）
    - 到 `vercel.com/drop` 把檔案拖進瀏覽器就上架；靜態網站不用帳號
    - 沒登入時網址是臨時的，成功頁有倒數；註冊免費帳號認領才保留
    - 已登入時可選團隊、填專案名稱，直接上到正式環境
  - **Gemini Canvas**（Google 說明頁，摘自前一版設計）
    - 免費，需登入 Google 帳號；未滿 18 歲不能用 Canvas 做網頁
    - 免費額度每 5 小時恢復、另有每週上限，數字未公布；免費版 context 約 32k token
    - 分享連結是公開的、沒有密碼，只能在 `gemini.google.com` 打開
    - 官方匯出只有 Docs、Slides 與複製內容，而且寫在「在電腦上」；沒有下載 HTML 檔的按鈕
- 未能查證（列入〈課前必測〉）：Gemini 免費帳號與手機能不能用 Skills；ChatGPT 免費版 Canvas 目前能不能預覽 HTML、手機能不能用；Claude 免費版 Artifact 能不能直接出單一 HTML 預覽

## 新增內容
### 手搖飲（Prompt）
- 情境：去手搖飲店點飲料。「一杯奶茶」拿到全糖正常冰 →「半糖少冰」接近了 →「半糖少冰，珍珠換椰果」就是這杯。不滿意就再調一次
- 揭曉：Prompt 是你給 AI 的指令，也就是點餐單；一次次調得更好，就是 Prompt Engineering（提示詞工程）
- 接法：前一頁剛揭曉「它不認識你，因為你什麼都沒說」，手搖飲接「說得越具體，拿到越對的東西」
- 來源：[2026-10-20 名詞設計](2026-10-20-ntut-section2-terms-design.md)〈Prompt〉、版型見 `docs/ntut-ai-course/mockups/section2/版型選項-已選B.html`
- 用詞統一成「點餐單」，咖啡店章節裡的「客人的訂單」跟著改

### 咖啡店 Skill 章節
- 7 頁原始檔在 `docs/ntut-ai-course/skill-chapter/slides/`（1920×1080 的單頁 HTML，每頁結尾 `<aside>` 是 30–60 秒講稿與銜接語），順序見同資料夾 `deck.json`；預覽在 <https://claude.ai/artifact/RocLz8n8xJKdn94GvFDBis>
- 比喻：AI Agent＝店員、Skill＝工作手冊、Tool＝咖啡機、Prompt＝點餐單
- 頁序
  1. AI 也需要工作手冊嗎？（店員、手冊、咖啡機三張插圖）
  2. 沒有 Skill 和有 Skill，差在哪？「沒有 Skill」分頁：牛奶灑了整桌的照片
  3. 同一頁切到「有 Skill」分頁：愛心拉花照片；註明 Skill 不保證 100% 正確
  4. 打開 AI 的工作手冊（資料夾結構，SKILL.md 是核心）
  5. 原來 Skill 就是一份 Markdown 文件（Metadata、Instructions、Rules）
  6. 從一句話到完成任務（6 步；Prompt 說要做什麼、Skill 說怎麼做、Tool 負責做）
  7. 把工作經驗變成 AI 可以重複使用的能力（生活、辦公、工程三個情境）
- 要補的銜接（講師同意）：這一章講的是「店員自己去書架找手冊、用咖啡機做」，但今天大家用的聊天 AI 不會自己去找手冊，所以要你親手遞給它。Gemini 的 Skills 是幫你把手冊收好，打 `/` 就能遞出去
- 表定 5 分鐘；講稿加總約 4.5 分鐘
- 兩張拿鐵照片是講師提供的，沒有放進 repo；來源與授權由講師確認後再放進 Synora

### 動手做自己的 Skill
- 目的：把剛剛做網站用到的做法打包，下次不用重打；這是學員今天帶走的第三樣東西
- 步驟
  1. 在做網站的同一個對話貼「Skill Prompt」，AI 把三個空格的答案與規則整理成三欄
  2. Gemini 學員：側邊欄「自訂 → Skills → 建立 → 手動建立」，把三欄貼進去
  3. 其他工具或建不了的人：把三欄存成文字，放在基本資料副本旁邊
  4. 確認：Gemini 學員在對話打 `/名稱`，加一句「先不要做，告訴我你會照哪些規則做」
  5. 上傳 Synora：貼三欄文字；Gemini 學員可附一張建好的畫面截圖
- Skill Prompt 草稿（Claude 擬的，講師未逐字確認）
  ```
  把我們剛剛做網站的做法，整理成一份可以重複使用的 Skill。只整理，不要重做網站。
  分三欄輸出：

  名稱：英文小寫，單字用 - 連接（例如 my-job-site）
  說明：一句話，說明什麼時候該用這份 Skill
  指示：
  - 給誰看：＿＿
  - 風格：＿＿
  - 最想讓對方記住的一件事：＿＿
  - 規則：只用我提供的基本資料，不編造；手機看也要好看；不放身分證、住址、私人手機
  ```
- 咖啡店第 5 頁教的 Metadata（名稱、用途）、Instructions、Rules，對應這裡的名稱與說明、指示、規則；投影片要點出這個對應

- 兩個情境沿用 [2026-10-20 名詞設計](2026-10-20-ntut-section2-terms-design.md)〈Context〉與 `docs/ntut-ai-course/mockups/section2/context-定案.html`
  - 一天上八堂課，第八堂剛下課，早上第一堂教了什麼？
  - A 老師在三個科目之間跳來跳去，B 老師整堂只講一件事，哪一堂記得多？
- 八堂課的說法要改：不說「越早越模糊」的固定遞減，改說「對話越長，前面的內容越可能被忽略或擠掉」。原設計的八根遞增長條圖要跟著調整，不能畫成固定由淡到深
- 揭曉：Context＝AI 在這段對話裡看得到的所有內容；結論只留一句「一個對話只做一件事」。不使用「Context Engineering」一詞（講師先前要求）
- 互動示意圖
  - 參考檔：`docs/ntut-ai-course/references/llm-context-window-interactive.html`（講師提供）
  - 沿用的呈現方式：中間一個「AI 這一輪看得到的內容」的框，上方顯示用掉多少容量；每按一次多一則訊息從下面疊上去；塞滿後最舊的內容變成虛線並標示沒有送進這一輪，或被壓成一段摘要；可逐步按、可重設
  - 內容換成學員今天自己的對話，依序：訪問卡 → 五題問答 → 我的基本資料 → Prompt ② → 網站 v1（很大一塊）→ `fix:` → 網站 v2（又一大塊）→ 視窗滿了，最早的訪問問答被擠出去
  - 最後一步：開新對話，框裡只有「基本資料副本＋一句新任務」，容量很空
  - 不用 RAG、Transformer、recency bias、token 這些詞；容量用百分比或格數表示，並註明是示意、不是任何產品的實際數字
- 省額度的說法：Google 說明頁寫額度跟對話長度有關，所以「對話越長也越耗額度」

## Prompt 變動
- **訪問卡**：用 PR #41 的 5 題版；拿掉「存成 `my-site/我的基本資料.md`」，改成「最後整理成一段『我的基本資料』」；提示「等一下同一個對話直接做網站」
- **Prompt ①**：改成聊天版，不讀檔、不寫回檔案；結尾要 AI 重新輸出完整的「我的基本資料」，方便整段複製存副本
- **Prompt ②**：用前一版設計的 Canvas 參考稿
  ```
  請用 Canvas（Claude 用 Artifact）幫我做一個個人求職網站，輸出成單一 HTML 檔。

  給誰看：＿＿（例如：面試官、客戶、社團學弟妹）
  風格：＿＿（填找風格投票選到的風格名稱）
  最想讓對方記住的一件事：＿＿

  rule:
  - 只用上面整理好的「我的基本資料」，沒有的就不要寫，不要編經歷、數字或獎項
  - 資料裡標「？」的地方直接略過，不要補
  - HTML、CSS、JavaScript 全部寫在同一個檔案，不引用外部圖片
  - 手機看也要好看，第一眼就看得出我是誰、想做什麼工作
  - 不要放身分證、住址、私人手機
  ```
  停損重開新對話時，最後加一段貼上基本資料副本
- **Prompt ③ 讀者審稿**：骨架不變（你是＿＿，看 30 秒，告訴我記住了什麼、想跳過哪裡、還想知道什麼）；拿掉「打開 `site/index.html`」，改成「看上面這個網站」
- **`fix:`**：格式不變（`fix:【哪一區】【要改什麼】`）；拿掉「rule: 只改 `site/index.html`」，改成「其他地方不要動」
- **Prompt ④（Vercel 上線）、Prompt V1（Vercel 登入）、打招呼卡、安裝指令**：全部拿掉
