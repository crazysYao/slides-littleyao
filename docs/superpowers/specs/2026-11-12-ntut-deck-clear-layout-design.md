# 北科大求職網站課簡報：清楚版面＋動畫改版設計

> 狀態：草稿，待講師核准（2026-11-12）
> 對象簡報：Synora 專案「讓 AI 一開口就懂你（求職網站上線版）」`aef695ce-dd63-4375-a02a-d134f3100159`，51 頁
> 內容來源：`docs/ntut-ai-course/synora/job-site-content.mjs`（文字、講稿、互動題目都在這裡）

## 為什麼要改
講師拿 Eric「新竹將軍村」簡報第 20 頁（`jj-setup1`「一鍵安裝：複製，貼到終端機」）當典範，原話：「這個畫面就是最好的典範，方便易讀」，並要求「全部都改成這種清楚版面」，同時導入動畫。

典範頁好讀的三個原因（講師看過對照後未反對）：
1. **步驟一眼看完**：標題下一排編號膠囊 `1 打開準備頁` `2 按「複製」`…
2. **順著視線走**：左邊「去哪裡做」→ 箭頭 → 右邊「做完會發生什麼」
3. **示意畫面會動**：照步驟依序演出（游標、貼上格亮起、訊息一行行跳出、完成提示），9 秒一輪循環

我們現在的操作頁（第 15、17、21 頁）是終端機在上、複製卡在下，步驟是擠在複製卡右上角的灰色小字，示意畫面靜態。

## 目標
- 51 頁全部改成典範的視覺語言：清楚的標題層級、編號膠囊、左→右對照、白卡＋色條、深色示意視窗
- 操作頁（15、17、21）做成典範那種循環示意動畫
- 每一頁都有進場動畫
- 截圖、課後 PDF、縮圖顯示動畫跑完的最終畫面，不能有空白或半透明

## 非目標
- 不改任何文字內容、講稿、題目、頁數、頁序（仍是 51 頁）。唯一的變動是把既有的箭頭字串拆成膠囊（規則見「實作者的決定」）
- 不動共用的 `build-deck.mjs`，也不動另外兩份簡報（`content.mjs` 提問力、`topic-f-content.mjs` 主題 F）
- 不加第 46 頁 Prompt ④ 的操作示意（講師在選項中沒選；可另案）
- 不改互動元件本身的行為與設定

## 反目標（做了就算失敗）
- 畫面一直在動：只有操作示意可以循環；其他動畫跑一次、1 秒內結束就靜止。不學 Eric 那些持續搖晃的裝飾（`swing`、`sway`、`awning`、`spin`）
- 截圖或 PDF 出現空白頁、元件只顯示一半
- 互動元件（投票、搶答、複製卡、文字雲、作業、作品牆、上線牆、連結、下載）被 HTML 蓋住而按不到
- 換成 Eric 的綠色、他的頁首頁尾、他的署名或他的安裝內容

## 已定的做法
### 架構（照 Eric 簡報）
Eric 的 80 頁每頁都是一塊 `html` 元件鋪滿 `0,0,960,540`，裡面放所有靜態文字、卡片、示意畫面和 `@keyframes`；互動元件用原生元件疊在上面（例如第 14 頁：html 底圖＋`copycard` 在 `44,50,872,462`）。我們照這個架構：
- 每頁一塊滿版 `html` 底圖，承載標題、內文、卡片、膠囊、示意視窗與動畫
- 互動元件維持原生，疊在底圖上方；元件型別與設定照現有 `build-deck.mjs` 產出的欄位不變，只可能調整位置大小以配合新版面

### 視覺語言
- 配色沿用 `job-site-content.mjs` 的 `palette`（黃 `#f5b400` 只當填色、上面放黑字；墨色 `#16161a`；底 `#fbfaf7`）
- 從典範借的構件：頁首色帶、粗大標題、編號膠囊列、白卡＋上緣色條、左右對照＋中間箭頭、深色示意視窗（標題列三個點＋「示意畫面」標籤）、底部連結列
- 畫布 960×540（與現在相同）

### 動畫
- 進場：標題、膠囊、卡片、條列依序淡入上浮；整頁 1 秒內跑完
- 操作示意循環（第 15、17、21 頁）：約 9 秒一輪，依步驟演出；我們的「複製」是學員要真的按的原生複製卡，所以示意只演「貼上之後」那段（貼上格亮起 → 訊息逐行出現 → 完成提示），不演游標去按 HTML 裡的假複製鈕
- `prefers-reduced-motion` 與 `window.__SYNORA_CAPTURE__ === true` 時直接顯示最終狀態（Synora 規定：截圖訊號在作者程式前設定）

### 程式位置
- 新增 `docs/ntut-ai-course/synora/build-deck-html.mjs`，只服務 `job-site-content.mjs`；輸出同樣的 deck JSON 格式
- `check-deck.mjs` 照舊要能跑過 `--sections --expect-pages=51`
- 教案 `job-site-syllabus.md` 的「檔案」段改成新的產生指令

### 實作者的決定（審查後補，講師可推翻）
- **截圖佔位框留原生**：第 3 頁 `s1-goal`、第 11 頁 roadmap 三站、第 29 頁颱風兩個假網站，這些講稿寫明課前要換成真截圖的框，維持獨立的原生 `svg` 元件疊在 HTML 底圖上，講師仍可在 Synora 編輯器直接換圖。2026-11-12 查過線上版 `saveSeq` 2，與推送時相同，還沒有人手換
- **膠囊只從複製卡標題拆**：只拆 `cardTitle` 裡含「→」的 6 串（`job-site-content.mjs` 第 198、226、260、313、393、595 行），封面副標等其他字串不拆。第一段若不是「複製」，就當作這張卡的名稱，不編號，例如「打招呼 → 複製 → 貼到 OpenCode → 傳送」變成卡名「打招呼」＋膠囊 `1 複製` `2 貼到 OpenCode` `3 傳送`。不補任何原本沒有的字
- **複製卡標題改成卡名**：為了不讓同一串字在膠囊和複製卡標題各出現一次，複製卡的 `title` 改成上面拆出的卡名；第 226 行沒有卡名，改用該頁的 `tag`（「安裝 · Windows」）。這是唯一改到互動元件設定的地方。第 484 行沒有箭頭，維持原樣
- **滿版互動頁不縮元件**：投票、多選、搶答 ×6、文字雲、作品牆、上線牆共約 14 頁，元件維持現在的滿版大小，避免擠到選項。HTML 底圖只提供底色與頁首，這些頁的進場動畫幾乎看不到，屬於預期結果

## 驗收
1. `check-deck --sections --expect-pages=51` 與 Synora `doctor` 通過
2. Synora `layout --view=both` 沒有出界、裁切、互相遮擋的回報
3. `render --view=both` 全 51 頁截圖逐頁看過：沒有空白、沒有半透明殘影、互動元件完整
4. `preview --view=both` 確認動畫會跑、互動元件按得到
5. Synora 規定 HTML 動畫要在真正的講師端與學員端驗證「切到該頁時動畫會播放、操作不妨礙換頁」。做不到就在報告標成未驗證，不用縮圖代替
